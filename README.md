# AgentFlow · 多 Agent 协同的智能办公数据处理平台

把一句话办公需求，变成**可校验、可追溯、可控成本**的自动化执行。

> 从单 Agent 工具（`../excel-mcp-agent`，Excel MCP Agent v1）演进而来：
> v1 证明"能让大模型填表"；本版解决"多个 Agent 协同 + 结果可信 + 成本可控"。

---

## 架构总览

```
                        ┌───────────────────────────┐
                        │      WebUI  /  CLI        │  ← 两步式：先看计划，再确认执行
                        └─────────────┬─────────────┘
                                      ▼
                ┌──────────────────────────────────────────────┐
                │            Orchestrator（状态机）             │
                │  规划 →(审批)→ 检索 → 执行 → 校验 →          │
                │                        ↑      │ 失败          │
                │                        └──重规划──┘           │
                └───────┬──────────────────────────────────────┘
                        ▼
     ┌──────────┬───────────┬──────────┬───────────┬───────────┐
     │ Planner  │ Retrieval │ Executor │ Verifier  │ Reporter  │
     │  规划     │   查数     │  执行     │ 校验(代码) │  报告      │
     └────┬─────┴─────┬─────┴────┬─────┴─────┬─────┴─────┬─────┘
          └───────────┴──────────┴───────────┘           │
                        │                                      │
                 ┌──────▼───────┐                    ┌─────────▼────────┐
                 │  Blackboard  │                    │ Trace · Budget   │
                 │  共享状态     │                    │ 轨迹 · 成本分账   │
                 └──────┬───────┘                    └──────────────────┘
                        ▼
        ┌──────────────────────────────────────────────┐
        │  Registry（20 个工具） · MCP Server           │
        │  Excel 读写 / 比对查重 / 联网检索             │
        └──────────────────────────────────────────────┘
```

**一句话原则**：LLM 只做决策，代码守底线（读写、校验、预算、溯源全部由代码完成）。

## 亮点速览

- **5 角色 Agent 协同**：Planner / Retrieval / Executor / Verifier / Reporter，共享黑板状态机
- **确定性校验**：Verifier 不调用大模型（完整性 / 溯源 / 一致性 / 查重），杜绝多 Agent 幻觉叠加
- **校验失败自动重规划**：带失败项回到 Planner 重做，而非原地重试
- **并行执行**：多文件线程池批处理，17 文件 / 281 项实测提速约 1.7 倍
- **全链路护栏**：写前备份、写后校验、Token 预算熔断、数据强制溯源、写入沙箱、人工审批
- **真实 A/B**：对账任务 tokens 较单 Agent 基线降低 **64%**，正确率持平
- 通用引擎 + 场景模板：对账 / 清洗 / 批量填报，**换场景零代码**

## 1. 为什么是多 Agent，而不是一个更大的 Prompt？

单个 Agent 干所有事，会出现三个典型问题：

1. **职责混淆**：规划、查数、写表、校验混在一个循环里，出错难定位；
2. **幻觉叠加**：模型既当运动员又当裁判，写了错值没人纠；
3. **成本失控**：所有决策都走 LLM，token 消耗不可控。

AgentFlow 把职责拆开，并规定：**LLM 只做决策，代码守底线。**

```
用户一句话
   ↓
Orchestrator（状态机：只决定交给谁 / 是否重试 / 是否终止）
   ↓
Planner → Retrieval → Executor → Verifier → Reporter
   ↓
Blackboard（共享状态） + Trace（可观测） + Budget（预算护栏） + Registry（工具层）
   ↓
Excel 文件 / 互联网
```

## 2. 五个 Agent 的边界

| Agent | 职责 | 是否用 LLM | 明确不做 |
|---|---|---|---|
| **Planner** | 理解任务、扫描结构、产出可执行计划 | 是 | 不写任何文件 |
| **Retrieval** | 联网收集外部数据，每条都带来源 | 是 | 不猜值、不写文件 |
| **Executor** | 按计划写入表格（复用 Excel 工具链） | 是 | 不判定对错 |
| **Verifier** | **确定性**校验：完整性 / 溯源 / 一致性 / 重复 | **否（纯代码）** | 不修改数据 |
| **Reporter** | 汇总黑板与轨迹，生成可交付报告 | 可选 | 不编结论 |

关键设计：**Verifier 的判定用代码写死**（如"写入值必须等于检索到的值"），
LLM 只负责解释，从而堵死"多 Agent 互相放大幻觉"的路径。

## 3. 通用引擎 + 场景模板

"换场景 = 换一个 JSON"，不改代码。内置三个场景：

| 场景 | id | 联网 | 说明 |
|---|---|---|---|
| 多表核对 / 对账 | `reconcile` | 否 | 按关键列比对两张表，输出差异 |
| 批量填报（行情查价） | `quote_fill` | 是 | 查价格并批量回填 |
| 数据清洗 / 补全 | `clean` | 否 | 查重复、找缺失、按来源补空值 |

## 4. 全链路护栏

- **写前自动备份**、**写后代码级校验**；
- **全局 Token 预算**（所有 Agent 共用一个池），超限立即熔断并如实记录；
- **数据必须可溯源**：每条值记录 source / confidence，查不到标 `not_found`，**绝不编造**；
- **确定性兜底**：若 LLM 没真正写入，由代码 `deterministic_write()` 补上，任务不会空转；
- **人工审批门**：先生成计划再确认执行；可开启只读试跑 `--dry-run`。

## 5. 可观测 / 可回放

每次运行的 **黑板 + 轨迹 + 报告** 全部落盘到 `storage/runs/<run_id>/`：
- 每一步：谁、调了什么工具、参数、结果、耗时、token；
- 每个 Agent 的 token / 成本分账（WebUI 面板 & 报告表格）；
- 可回放、可评测、可对比。

## 7. 测试与评测

```bash
python tests/test_core.py         # 确定性内核（预算/黑板/比对/校验规则）
python tests/test_multiagent.py   # 多 Agent 编排（MockLLM，零 API 成本）
python tests/test_webui.py        # WebUI 冒烟

python tests/eval/run_eval.py --mock    # 评测自检（离线）
python tests/eval/run_eval.py --real    # 真实评测 → 产出 A/B 对照表
```

`run_eval.py` 会对比 **多 Agent（v2）** 与 **单 Agent（基线）** 的成功率、差异识别正确性、
严重错误数、tokens、成本、工具调用与耗时，输出到 `storage/eval/`。`--repeat N` 可多轮取平均。

**真实评测结果（同一模型，每任务 3 次取平均）**：

| 任务 | v2 成功率 | 基线成功率 | v2 平均 tokens | 基线平均 tokens | 变化 |
|---|---|---|---|---|---|
| 多表核对 | 3/3 | 3/3 | 29,344 | 81,429 | **−64%** |
| 数据清洗 | 3/3 | 3/3 | 31,732 | 32,777 | −3%（持平） |

> 结论：在结果正确率相同的前提下，多 Agent 版在"多表核对"这类任务上成本显著更低；
> 更重要的是，v2 的结论由**确定性校验**背书，而基线没有独立校验环节，其"正确"不可验证。

## 9. 设计取舍（面试可讲）

- **编排自研轻量状态机，不用 LangGraph**：多 Agent 的核心是"可控、可观测、可回放"，
  自研状态机能精确控制预算、审批门与轨迹，也避免"框架套壳"。
- **Verifier 不调 LLM**：判定必须可复现；把 LLM 从"裁判"位置上拿下来，是可信度的前提。
- **确定性兜底**：不假设 LLM 一定听话，用代码保证"任务要么完成，要么如实报告未完成"。
- **场景配置化**：证明引擎是通用的，"同一套引擎适配不同客户场景"。

## 10. 与 v1 的关系

- v1（`../excel-mcp-agent`）：单 Agent + MCP 工具，验证"大模型能安全地填 Excel"。
- v2（本项目）：在其之上拆出多角色协同、共享黑板、确定性校验与预算分账。

v1 保留原样，用于 `run_eval.py` 的 A/B 对比叙事。

## 11. 安全与边界

- **API Key** 只从 `.env` / 环境变量读取，永不写入代码、报告或轨迹；`.env` 已被 `.gitignore` 忽略。
- **WebUI 默认只监听 127.0.0.1**，不对外暴露；执行采用"先看计划、再确认"的两步式。
- **写操作**有备份 + 校验 + 可选人工审批门；`--dry-run` 可完全禁止写入。
- **写沙箱**：设置 `AGENTFLOW_SANDBOX=1` 后，写操作只允许写入 `data/` 目录内部。
- **防公式注入**：写入的字符串若以 `= + - @` 开头会被强制按文本写入。
- **防 XSS**：WebUI 所有动态内容渲染前均做转义。
- **已知风险**：`fetch_web` 会抓取模型给出的 URL（SSRF 面），且网页内容可能携带提示注入；
  因此本项目把"校验与写入"解耦，并建议演示时开启 dry-run 或限制沙箱。生产化仍需域名白名单与鉴权。

## 13. v2.1 升级：重规划 & 并行执行

**重规划（Re-plan）**：校验不通过时不再"原地重试"，而是带着**上一轮的失败项**回到 Planner 重新制定计划，
再执行、再校验（默认最多 1 轮，可配 `max_replan_rounds`）。这样模型能针对失败原因换打法，而不是重复同样的错误。

```
执行 → 校验 →（不通过）带失败反馈重规划 → 执行 → 校验 → 通过 → 报告
```

**并行执行（Parallel）**：新增 `batch_fill_many` 工具，基于线程池并行处理多个文件；`deterministic_write`
与校验（查重）也都改为并行。备份文件名生成加了互斥锁，避免并发写入时时间戳撞车。

实测（17 张报价表 / 281 项）：串行 `2.07s` → 4 线程 `1.22s`，约 **1.7x** 提速。

> 并行边界：文件之间相互独立（各自 openpyxl 读写与备份），因此可安全并行；
> Agent 之间仍通过共享黑板串行协作，不做并发写黑板，避免状态竞争。
